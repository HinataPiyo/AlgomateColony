# AlgomateColony — Game Overview

## この資料の読み方

本書は、既存のREADME、企画資料、ソースコード、Unityアセットを照合した作品紹介です。

- **企画上の意図**は `README.md`、`Assets/Docs/story.md`、`AlgorithmColony_Memo.md` に記された内容です。
- **実装済みの事実**は、コード・設定データで確認できた範囲を指します。Unity Editorでの通しプレイ確認を意味しません。
- **提案・解釈**は開発者が明示した決定ではなく、ポートフォリオで説明する場合の候補です。

## コンセプト

既存の企画資料では、プレイヤーがロボット「アルゴメイト」に命令を与え、資源の収集・運搬を組み合わせてコロニーを発展させる構想が示されています。`Assets/Docs/story.md` は「直接操作より計画」「命令の最適化」「コマンド理解と成長」を体験の軸として掲げています。

現在のコードで確認できるのは、`Move`、`Gather`、`Deposit` の入力列をロボット状態へ変換し、探索・移動・採集・倉庫格納へつなぐ仕組みです。条件分岐や一般的なプログラミング言語を備えたコマンドエディタではありません。

### 企画資料に記された世界観

`Assets/Docs/story.md` は、荒廃した惑星に降り立ったプレイヤーが、稼働限界に近いロボットを再起動し、失われた文明の技術を集めながら新たな拠点を築く背景を記載しています。過酷な環境、資源やエネルギーの不足、研究を通じた自動化の発展も企画上の設定です。これらは世界観の説明であり、現行コードに惑星探索、文明技術の収集、研究進行が実装されていることを示すものではありません。

### 企画資料で明示されている体験の軸

既存の企画資料が明記する体験の軸は「直接操作より計画」「自動化が回る快感」「命令最適化による達成感」「コマンド理解そのものが成長実感になる設計」です。また、世界観のトーンは、ロボティクスと資源物流を中心とし、戦闘よりシステム運営でコロニーを発展させる方向として記載されています。いずれも開発者資料に書かれた設計意図であり、プレイヤーへの効果がテストで検証された結果ではありません。

## 基本的なゲームループ

### 企画上の想定

1. ロボットを選ぶ。
2. ロボットに作業コマンドを入力する。
3. 実行結果を確認し、資源を集めて運ぶ。
4. 資源を拠点の発展に使う。
5. 拠点の進行を通じて次の施設・機能へ進む。

### 現行コードで追跡できる部分

1. `RobotStatusPanelManager` が選択されたロボットの状態・コマンドUIを設定します。
2. `RobotCommandUIController` が行ごとの入力を検証し、`RobotCommandExecute` に渡します。
3. アルゴメイトが対象を探索し、移動・採集・格納を行います。
4. 資源はロボット所持Slotから倉庫在庫へ移動できます。
5. `LocationController` は倉庫在庫を拠点レベルアップ必要数と比較し、レベルアップ操作で素材を消費して `SystemControlSO.LocationLevelUp()` を呼びます。

この一連の体験がUnity Editor／配布ビルドで最初から最後まで完了することは、本資料作成時点では実機確認していません。失敗時にコマンド完了通知が行われず、実行列が待機するコード経路もあります。処理の詳細は [LogicFlows.md](./LogicFlows.md)、現行ルールは [GameSpecification.md](./GameSpecification.md) を参照してください。

## 現時点のゲーム目標

- **企画資料にある目標**：コロニーを発展させ、自動化の規模・複雑さを増していくこと。
- **コードと現行チュートリアルデータから確認できる短期目標**：アルゴメイトを移動させ、資源を採集・倉庫に格納し、拠点レベルアップを行うこと。現行 `LocationLevelupUnlock.asset` はレベル0から次レベルへ進むためのデータを1件持ち、加工施設Prefabを参照しています。
- **要確認**：チュートリアル完了後の明確なエンディング、繰り返し可能な長期目標、加工施設解放後の完成したゲーム目標は確認できません。

## 現在実装されているプレイ体験

- コマンド入力欄に複数行の `Move(...)`、`Gather(...)`、`Deposit(..., ...)` を入力する。
- 石、木、鉄鉱石などを探索・採集し、アルゴメイトの所持Slotに保持する。
- 倉庫が近くにある状態で、指定素材・数量を倉庫へ格納する。
- 拠点パネルで次のレベルに必要な素材と在庫を確認し、条件成立時にレベルアップする。
- チュートリアルパネルに沿って操作手順を進める。

この説明は各処理のコード経路が存在することを示します。失敗条件や中断条件を含む詳細は [GameSpecification.md](./GameSpecification.md) と [ImplementationStatus.md](./ImplementationStatus.md) を参照してください。

## 作品として説明できる特徴

### コマンドをゲーム操作に取り入れた設計

既存の企画書は「ロボットに命令を与える」「命令を組み合わせて作業を自動化する」ことをゲームの中心に置いています。現行実装は、入力した文字列を検証し、ロボットの状態遷移とワールド上の行動に接続するところまで確認できます。

**価値の解釈（開発者への確認前の説明案）**：操作を「移動ボタンを押し続ける」方式ではなく、作業対象と行動を先に記述し、その実行を観察する体験として説明できます。ただし、なぜコマンド入力を採用したかという開発者本人の制作動機は既存資料に明記されていません。

### 命令するロボットと資源物流

`Move`、`Gather`、`Deposit` は、対象への接近、資源の所持、倉庫への移送という処理をコード上で結びます。企画意図の「直接操作より計画」と、現行のロボット状態機械・アイテムデータの関係を示せる題材です。コマンドの失敗時に実行状態が停止し得る点を含め、現時点でできることと改善余地を合わせて示すのが正確です。

### 資源収集から拠点発展まで

ロボットSlot、倉庫在庫、拠点レベルアップ素材は別のデータ構造・処理で管理されています。ロボットの採集物を倉庫へ移し、倉庫在庫をレベルアップに消費する経路があるため、ゲームの基本ループとデータ連携を一連の例で紹介できます。レベルアップの素材チェックと消費に成功結果の再検証がないなど、品質面は別途説明が必要です。

### ビジュアルの特徴：白黒基調は要確認

- 確認した `Robot_0_Idle.png`、`rock128.png`、`ground1_1.png`、`workshop1.png` は、黒・白・灰色の階調を使ったピクセルアートです。`BlackWhite.png` という名称のUI画像も存在します。
- これらのアセットは白黒・グレースケール表現を紹介する根拠になりますが、Scene全体のUI、照明、背景、他アセットを含む最終画面の色設計までは示しません。
- ポートフォリオでは「確認した主要Spriteにグレースケールのピクセルアートを採用」と限定して説明できます。「ゲーム全体を白黒基調にした意図」やそのデザイン上の狙いは、開発者への確認後に記載します。

### 他作品との差別化を説明する際の検証項目

競合作品との比較は、本資料では断定しません。ポートフォリオ上の独自性を説明する場合は、少なくとも以下を実際のゲーム体験・比較対象・仕様で確認してください。

- テキストコマンドの自由記述と選択式UIのどちらを中心にするのか。
- コマンドを複数行で実行する際、逐次指示と自律ルールのどちらを目標にするか。
- 学習支援（チュートリアル、エラー説明、使用可能命令の段階的解放）の具体的な仕組み。
- アルゴメイトの個体差、複数体の協調・役割分担が実装されるか。
- 他の自動化・コロニー運営ゲームとの共通点と、プレイヤーが実際に行う操作の違い。
- 白黒ビジュアル、SF世界観、ストーリーがゲーム体験にどう結びつくか。
